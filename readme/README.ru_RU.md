# Пользовательские маршруты OneXray

[English](../README.md) | [简体中文](./README.zh_CN.md)

Шаблоны для текущего редактора **пользовательской маршрутизации** OneXray,
включая настройку локального DNS. Это не подписки на серверы и не полные
конфигурации Raw JSON. Серверы необходимо добавить отдельно.

## Шаблоны

| Шаблон | Маршрутизация | Адрес локального DNS |
| --- | --- | --- |
| [Материковый Китай](../cn.json) | Локальные сети, домены Apple, домены и IP материкового Китая — напрямую; остальной трафик — через VPN. | `223.5.5.5` |
| [Иран](../ir.json) | Домены из иранского набора, частные и иранские IP — напрямую; остальной трафик — через VPN. | `5.200.200.200` |
| [Россия](../ru.json) | Домены и IP из российских списков блокировок — через VPN; остальные IP — напрямую. | `9.9.9.9` |

Каждый шаблон использует один входной узел. В редакторе можно выбрать два или
три. Шаблоны не привязаны к серверам и не настраивают конечный выходной узел.

## Импорт

1. Скачайте JSON для [материкового Китая](https://raw.githubusercontent.com/YuanDevTeam/Routing/main/cn.json),
   [Ирана](https://raw.githubusercontent.com/YuanDevTeam/Routing/main/ir.json) или
   [России](https://raw.githubusercontent.com/YuanDevTeam/Routing/main/ru.json).
   Либо скопируйте всё содержимое JSON, а не ссылку на файл.
2. На странице подключения откройте выбор способа маршрутизации трафика и
   создайте новый пользовательский маршрут.
3. В редакторе выберите импорт файла или чтение буфера обмена. OneXray скачает
   пользовательские Geodata, объявленные в шаблоне; нужен доступ к интернету.
4. Проверьте название, правила, число входных узлов и адрес локального DNS,
   затем сохраните маршрут.
5. Выберите сохранённый маршрут, укажите серверы и подключитесь.

Можно сохранить до трёх пользовательских маршрутов с уникальными названиями.
Если лимит достигнут, импортируйте шаблон в существующий маршрут для замены
его содержимого или сначала удалите ненужный маршрут. Не используйте для этих
файлов импорт серверов или Raw JSON.

## DNS и сопоставление правил

- Шаблон хранит только адрес локального DNS для прямых соединений.
  DNS через прокси управляется OneXray и использует `8.8.8.8`.
  Настройки DNS туннеля независимы от этих параметров.
- Домены для локального DNS берутся из правил с действием `direct`. Условия
  по IP, порту или сети не выбирают локальный DNS. Он не является общим
  резервным сервером.
- В российском шаблоне нет правил прямого доступа по доменам, поэтому
  сохранённый адрес `9.9.9.9` используется только после добавления таких правил.
  Запросы доменов идут через DNS прокси; прежний общий резервный Quad9 больше
  не используется.
- `IPIfNonMatch` разрешает не совпавший с правилами домен в IP и проверяет
  правила повторно. Последнее прямое правило российского шаблона охватывает
  `0.0.0.0/0` и `::/0`, а не весь TCP/UDP-трафик. Это позволяет проверить
  заблокированные IP после разрешения домена. Если DNS не вернул IP, это
  правило не сработает.
- Если ни одно правило не подошло, Xray использует первый выходной узел.
  Правила с явным действием VPN используют балансировщик `proxy`. Разные типы
  условий внутри одного правила связаны логическим И; значения одного типа — ИЛИ.

## Зависимости Geodata

Имена пользовательских файлов и HTTPS-адреса уже включены в `geodata.assets`.
Не добавляйте эти наборы вручную перед импортом.

| Шаблон | Файл | Источник |
| --- | --- | --- |
| Материковый Китай | `EnhancedGeoSite.dat` | [Loyalsoldier Geosite](https://github.com/Loyalsoldier/v2ray-rules-dat/releases/latest/download/geosite.dat) |
| Материковый Китай | `EnhancedGeoIP.dat` | [Loyalsoldier GeoIP](https://github.com/Loyalsoldier/v2ray-rules-dat/releases/latest/download/geoip.dat) |
| Иран | `IranGeoSite.dat` | [Iran hosted domains](https://github.com/bootmortis/iran-hosted-domains/releases/latest/download/iran.dat) |
| Россия | `RussiaGeoSite.dat` | [Russia Geosite](https://raw.githubusercontent.com/runetfreedom/russia-v2ray-rules-dat/release/geosite.dat) |
| Россия | `RussiaGeoIP.dat` | [Russia GeoIP](https://raw.githubusercontent.com/runetfreedom/russia-v2ray-rules-dat/release/geoip.dat) |

Иранский шаблон также использует категории `PRIVATE` и `IR` из стандартного
`geoip.dat` OneXray. Стандартные файлы не включаются в список зависимостей.
При конфликте имён пользовательских файлов импорт отклоняется без перезаписи.
Чтобы использовать уже установленный подходящий набор, удалите его запись из
списка зависимостей, не меняя ссылки в правилах. Иначе переименуйте файл и все
соответствующие ссылки `ext:` перед импортом. Не удаляйте наборы, нужные другим
маршрутам.

После успешного импорта OneXray удаляет список зависимостей из сохранённого
JSON маршрута и снова добавляет необходимые пользовательские зависимости при
экспорте.

## Формат

- `name`: уникальное название длиной 1–32 символа в импортируемом JSON.
- `dns.servers`: один объект только с `tag: "app-dns-direct"` и `address`.
- `outbounds`: от одного до трёх пустых объектов, например `[{}]` или `[{}, {}, {}]`.
- `routing`: `domainStrategy: "IPIfNonMatch"` и упорядоченный список `rules`.
- `geodata.assets`: необязательные зависимости импорта, только `file` и `url`.

Название правила задаётся через `ruleTag`. Поддерживаются условия `domain`,
`ip`, `port` и `network`. У каждого правила ровно одно действие:
`balancerTag: "proxy"`, `outboundTag: "direct"` или `outboundTag: "block"`.

Не добавляйте реальные узлы, определения выходов `direct`/`block`, `inboundTag`,
`type`, списки доменов или стратегии запросов DNS, а также определения
балансировщиков. OneXray создаёт зависимости для выполнения и проверяет
конфигурацию через libXray. Для полных конфигураций Xray используйте Raw JSON.
